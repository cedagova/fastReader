FastReader #46 — device backup evidence
Device: Phone_Mid_API36 (sdk_gphone64_arm64, Android 16 / API 36), adb root.

Same seeded data throughout: two books added through the picker, one opened and
read (so a reading position exists), settings written. Three builds installed in
place over that data, so nothing but the manifest differs between them:

  A  no allowBackup, no rules            — the collector base's behaviour
  B  allowBackup="true" + the new rules  — control: does the rules file work?
  C  allowBackup="false" + the new rules — the shipped head

Two transports, because the two halves of AD-11 are governed separately:

  com.android.localtransport/.LocalTransport                    cloud backup
  com.google.android.gms/.backup.migrate.service.D2dTransport   device transfer

For the local transport the proof is the stored blob under
/data/data/com.android.localtransport/files/1/_full/. The D2D transport does not
store there, so its measure is the byte progress the framework reports.

Result: A moves 9,728 bytes on both transports and the local blob contains
catalog.json, both cover files and the theme mirror. B and C move nothing on
either transport. C is additionally refused outright on the cloud path
("Backup is not allowed"), which is allowBackup="false"; on the device-transfer
path, which ignores that attribute, it is the rules file that empties the
payload — which is exactly what B isolates.
